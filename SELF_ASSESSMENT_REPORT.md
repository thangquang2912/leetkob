## What we did not manage

We completed all required deliverables for PA#2 (the assistant rules, three-tier permissions, four-check CI harness, protected `main` branch, `GET /labs/{labId}/review-queue` contract, contract tests, and deliberate break proofs). In PA#2 the review queue store is backed by an in-memory seed store (`src/store.ts`) rather than a persistent database, as database persistence, C++ sandbox execution, and live Gemini constraint checking are scheduled for PA#3.

## What we would do differently

We would define the raw query string validation rules before writing the route handler, rather than initially relying on framework-level query parsing and discovering during edge-case testing that duplicate query parameters (`?page=1&page=2`) and leading zeroes (`page=01`) were silently coerced. Also, on PR #1 we used GitHub's "Squash and merge" button before switching to "Create a merge commit" on PR #2 so both the red and green commits stay directly visible in the `main` commit graph as well as the PR branches.
